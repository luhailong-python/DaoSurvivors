# 整套 UI 流程与状态关系

2026-10-26。功能依据为 survivors-roguelike-kit 的提交 `3f905381d73a34b516030528b8ef6743868b9e52`。以下是**美术和状态设计合同**，不是可运行业务实现；不生成C#、Prefab或场景。整屏编号与 `UI_COVERAGE.json` 对应，可查看[Mermaid源图](flow.mmd)。

## 来源与范围

`existing`为参考已有功能，`supporting_state`为这些功能需要的展示状态，`suggested`为本次明确补充。主菜单、选角、选关、PowerUp、设置、战斗、升级、宝箱和胜负结算均有源码/配置证据；完整暂停菜单、消费确认、读取异常、保存提示及进化条件详情是本次设计补充。参考仓库仅用于研究；F盘仓库仅是美术来源；成果远端待用户提供。

此前 `Assets/` 中的Unity样稿已经冻结，不作为当前接入成果。本轮正式成品由 `art/`、`designs/ui-suite/` 和文档组成。旧九图的三关/90秒/三属性属于早期假设，新的52画面合同以实际两关、14项成长、6+6槽及宝箱进化流程为准。

## 主路径与返回

1. `01-startup`启动，进入`04-main-menu`山门。启动视觉与本地资源检查是补齐，不加入在线更新、登录或选服。
2. 主菜单四入口为新历练、温养根基、设置和退出。新历练打开`05-character-select`；已经解锁的人物可选，锁定人物显示500金币。
3. 已解锁人物确认后进入`12-level-select`。源有FirstLevel/SecondLevel两个配置，关卡说明和本次地点名分别注明来源；不能把共享Map/Stage说成两套已完成地图。
4. 选关确认进入`02-loading`，完成后显示`25-battle-hud`。加载无精确百分比契约，画面使用不定进度；异常走`03-loading-error`，重试或返回选关。
5. 战斗中靠近掉落即时拾取，经验积满打开`29/30/31`三选；选择后回战斗。该流程不是背包或商店。
6. 拾取宝箱走`32–36`，揭示后确认全部奖励再继续。进化只能由该路径触发。
7. 所有波次已启动且存活敌人归零进入`40-victory`；气血耗尽进入`41-defeat`。最后生成时间720秒不是固定720秒自动胜利，也不沿用旧90秒固定结算。
8. 结算退出将本局金币加入局外金币并回主菜单。`42-save-pending`与`43-save-error`是存档可见反馈补齐；确认/领取的进行中态应防重复，失败保留当前界面可重试。

选角返回主菜单；选关返回角色层；人物详情、秘境详情返回各自列表。PowerUp关闭回主菜单。设置从主菜单打开时返回主菜单，从暂停打开时返回暂停，不自行恢复战斗。三选与宝箱不提供直接返回主菜单的隐式领取路径。

## 角色解锁

`05`锁定条目 → `08-unlock-confirm` → 资金检查。足够时扣500金币、写解锁标记、显示`10-unlock-success`，再回角色列表；不足显示`09`并返回，人物仍锁定；取消消费回列表，金币与解锁不改变。源为直接点击购买，确认弹窗是本次补充。

已解锁与已选择分开表达，解锁成功不必强制切换当前角色。`06-character-owned`展示已解锁后的明确选中状态。空配置走`11-character-empty`，不留可确认的旧角色或不明默认图。

## 永久成长

`16-powerup-overview`14项网格 → 选择项 → `17-powerup-detail`。有金币且未满阶才允许购买；不足是`18`，满阶是`19`，成功是`20`并刷新当前阶数、下一阶价格和金币。不同字段分别使用真实1/2/3/5上限，不画统一五阶。普通、选中、不可购买、最高阶和升级反馈不能混为一种颜色。

源源码对不足/满阶主要静默返回，因此清楚原因文字属于展示补齐。原demo金币价格保存在清单；正式经济若后续改动，只改动态文字与数据，不重新烘焙底图。

## 局内升级、满槽与进化

主动和被动各6槽。未满槽可以出现未获得道法；满槽仍能升级已获得但未满级道法；没有可用升级才用钱袋补位。`29-upgrade-new`、`30-upgrade-existing`、`31-upgrade-moneybag`分别展示这些语义，不能将“满槽”等同“满级”。所有三选画面冻结战斗，选择1项后继续；未发现源重抽、跳过、放逐功能，不制作这些按钮。

`47-evolution-locked`和`48-evolution-ready`是建议道法资料界面，读取条件用来解释：需要指定的攻击道法与相应被动达到要求。条件未满足显示明确缺口；条件满足仅显示“已满足，等待宝箱机缘”。**这两张画面都没有立即进化、直接合成或消费进化按钮。**返回道法资料或此前上下文，不改变战斗技能。

实际触发顺序是战斗取得宝箱 → 从候选技能中优先纳入已满足混合条件的道法 → 宝箱揭示进化奖励 → 确认应用 → 返回战斗。对应`35-treasure-evolution`。源码位于 `Assets/RGame/RoguelikeKit/Scripts/System/Skill/SkillManager.cs`，不是不存在的`Scripts/Skill/SkillManager.cs`。

## 宝箱、揭示与确认

宝箱奖励数1/3/5；`32`和`33`可展示揭示阶段，`34`展示五件可确认，`35`展示进化，`36`展示无可升级项时的钱袋。约3秒揭示中确认按钮隐藏或禁用，结果明确后统一确认，技能和钱袋均应用全部。确认前后重复输入防护属于待接入验证要求。

揭示阶段不能把未获得的预览图标标成已激活技能；确认后回到同一局战斗，不跳回主菜单。奖励槽位数量以实际返回数量为准，不把`List.Capacity`潜在异常当成设计契约。

## 暂停、退出和设置

`37-pause`是本次建议补齐，源只有Pause/Unpause输入事件。暂停冻结计时、角色、妖灵和法术；继续回原战斗；设置返回暂停。`38-abandon-confirm`取消回暂停，确认结束走主菜单；放弃未结算收益的规则在本次设计中明确，源没有完整主动放弃流程，不冒称已有。

`39-exit-confirm`由主菜单退出入口打开，取消留在主菜单，确认才离开。源有Exit按钮但没有完整退出订阅证据，这里只交付确认/取消状态设计。

`21-settings-audio`包括主音量、音乐、音效三项；`22-settings-display`包括分辨率、全屏、伤害浮字；`23-settings-language`展示语言选择。切成页签是本次布局重设计，源原为7行。`24-display-confirm`是建议补齐的保留/还原安全返回；它不意味着源已实现自动倒计时恢复。源只有English(en)语言资源，本次中文是美术文案本地化。

## 辅助与异常状态

`44/45`帮助与引导说明移动、自动施法、经验、槽位、宝箱和进化；`46`道法资料、`49`属性页是对已有数据的可读展示建议，不能变成额外养成商店。`50`通知、`51`状态对照、`52`流程图是交付支持图，不增加独立游戏系统。

读取失败、存档失败、空角色、空关卡、尚未选择均保持清楚的返回路径，不依赖隐式鼠标热区。错误状态的按钮和背景应与所在上下文一致，不能把失败提示叠在已成功领取画面上。
